## You are continuing 4NSEC

4NSEC (repo `boode-hub/sharingan-forensics`, live at
https://boode-hub.github.io/sharingan-forensics/) is a browser-only
replacement for **all of Eric Zimmerman's forensic tools**. An analyst drops
artifacts onto the page; every byte is parsed in a Web Worker in that tab and
shown in one grid with search, a condition builder, Sigma rules, saved filters
and CSV/JSON export. It must work for live forensics on a machine where
nothing may be installed and nothing may leave.

The owner's standard, in their words: "literally convert his code … without
any sacrifice", "no shortcuts or data behind", "list all the content". A
parser is done when its output matches what his tool prints: same records,
same columns in the same order, same values rendered the same way.

## Non-negotiable rules

1. **No network calls** in shipped code: no fetch/XHR/WebSocket/beacon, no
   CDN, no remote fonts. CI greps for them. Evidence never leaves the machine.
2. **Port his source, do not reinvent.** Clone his repo into `.refs/`
   (git-ignored) and translate his classes. Write from a format spec only when
   no EZ source exists (say so in the file header). Keep his quirks and say so
   in a comment; where his code would *throw* or *drop* a record, keep the
   record, fill what was read, and `ctx.warn` why.
3. **Parser contract** (`src/core/types.ts`): async generator yielding rows,
   read through `reader.bytes()` (never the whole blob for big inputs),
   timestamps `Date | null` (never 0 or epoch as "missing"), never throw on
   bad data. `types.ts`, `registry.ts`, `binary.ts` are the contract: change
   them only minimally and call it out.
4. **No new dependencies** without naming what they replace and why the
   platform cannot do it (SPEC mentions sql.js for SQLite; decide explicitly
   before adding it).
5. **Never commit real evidence.** Real artifacts for local testing go in
   `public/_t/` (git-ignored) and are deleted after. Committed fixtures are
   either his MIT test files or generated by a `fixtures/<id>/make.mjs` that
   CI re-runs byte-for-byte. Record provenance in `fixtures/SOURCES.md`.
6. **Never write secrets to disk** (API keys, tokens), not even in scratch
   files.
7. **Verify before claiming.** Every parser is checked against an oracle that
   is not itself: his published test assertions, Windows' own rendering, an
   independent count, or a cross-structure consistency check. Run the real
   commands and paste real output; never report "should work".

## How a tool gets ported (the loop that has worked)

1. `git clone --depth 1 https://github.com/EricZimmerman/<Repo>.git .refs/<Repo>`
   for the library *and* the CLI (the CLI's `Program.cs` holds the CSV map).
2. Read his parser classes and his CSV output class/map. Column order is his
   CSV header. If he uses CsvHelper `AutoMap` plus `.Index()`, unindexed
   properties land where .NET's introsort puts them; simulate it (see the
   Amcache port for the method) rather than guessing.
3. Port into `src/parsers/<id>.ts` (+ `src/parsers/<id>/` for generated
   tables). Shared structures live in `src/core/`: `shellitem.ts` (all shell
   items), `propstore.ts` (property stores), `cfb.ts` (OLE compound files),
   `binary.ts`, `textdate.ts`. Hive-based artifacts use `openHive()` from
   `src/parsers/registry/hive.ts` (log replay + deleted keys attached as his
   RegistryHive does). Big lookup tables are generated by `scripts/*.mjs` from
   his resource files and imported lazily.
4. Several record kinds = `Parser.tables` (one table per CSV he writes; rows
   carry `table`). The UI shows one tab per non-empty table.
5. Register in `src/parsers/index.ts` (order matters when two sniff the same
   magic: the specific one first). Add `fixtures/<id>/`; `detect.test.ts`
   requires one per parser.
6. Tests: his assertions verbatim, plus at least one independent check.
   Before committing a change to shared code, diff old vs new output over his
   full test corpus (e.g. the 1,002 LNKs in `.refs/Lnk/Lnk.Test/TestFiles`)
   and review every changed value.
7. Local real-data run (not committed): e.g. `%APPDATA%\Microsoft\Windows\Recent`
   jump lists, `wevtutil epl` exports. Report counts only.
8. `npm run typecheck && npm test`, `npx oxlint src`, `npm run build`, then
   verify in the browser pane (drop files via a DataTransfer from
   `public/_t/`). Commit with a message that says what and why, push to
   `master`; CI rebuilds fixtures, tests, builds and deploys Pages.

## Gotchas that have cost time

- `npm run typecheck` (`tsc -b`) — plain `tsc --noEmit` checks nothing here.
- Bash heredocs eat backslashes. Write any code or JSON containing `\` with
  the file Write/Edit tools, never through `cat <<EOF` or `python - <<EOF`.
- Vitest swallows `console.log`; dump debug output to a file.
- The grid deliberately ignores `Column.secondary`: nothing is hidden by
  default ("a column you cannot see is evidence you do not know exists").
- localStorage keys keep the old prefix `4ensics.` so settings survive the
  rename to 4NSEC.
- Row limit is `MAX_ROWS` in `src/core/registry.ts`; parsers import it.
