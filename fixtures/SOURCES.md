# Fixture provenance

No fixture here is real evidence, and none was taken from a real investigation.

Fixtures are either **generated by a `make.mjs`** beside them from the
documented on-disk layout, or **produced by Windows itself** where Windows is a
more authoritative source for the byte layout than a hand-written generator.

Generating them matters twice over:

- Real forensic artifacts carry real usernames, paths and timestamps. They do
  not belong in a public repository.
- A generated fixture is an **independent oracle**. It is written from the
  format documentation, or from what Windows was asked to create, rather than
  from parser output — so a parser that matches it is agreeing with the format
  and not merely with itself. A sample captured from a parser's own output can
  only ever confirm that parser's bugs.

CI regenerates every `make.mjs` fixture and fails if the committed bytes drift,
so those samples can always be audited against the generator that claims to
produce them.

## Note on `lnk/notepad.lnk`

This is a genuine Windows shortcut, created by asking `WScript.Shell` for a
shortcut to `notepad.exe` with a known set of properties. Windows wrote the
bytes, so the layout is authoritative in a way a hand-rolled generator would
not be, and the expected values are simply the properties that were requested.

It has no `make.mjs` because it cannot be regenerated on the Linux CI runner, so
the reproducibility check skips it.

Two identifiers were **sanitized** after generation, because a real shortcut
carries machine identity that has no business in a public repository:

- the TrackerDataBlock MachineID was replaced with `TESTHOST`
- the Droid and DroidBirth GUIDs were zeroed, as they are version-1 UUIDs that
  embed the network adapter's MAC address

The volume serial number `107F8885` was deliberately left intact. A volume
serial is not personal data, and parsing it correctly is exactly what the
fixture needs to prove.

If a real-world sample is ever added, it must come from a public corpus with a
licence permitting redistribution, and the licence and source URL must be
recorded in the table above.

## Note on `prefetch/DEVENV.EXE-854D7862.pf`

The one real-world sample here. It comes from the test corpus of Eric
Zimmerman's own Prefetch library, which is MIT licensed and therefore
redistributable, and it is test data rather than evidence from an
investigation.

It is committed because the Xpress Huffman decompressor cannot be exercised
without it. The synthetic MAM fixture beside it contains only literals, so it
proves the container and the Huffman table but never a back-reference across a
chunk boundary. This file decompresses to 380690 bytes, six chunks, and does
reach across them.

It carries its own oracle: the file-metrics count in its header says 403
entries, and a valid Prefetch file has exactly that many filename strings, so
any decoder that produces a different number is provably wrong.

## Note on `registry/`

`SAM` is a genuine clean registry hive and `NotAHive` is a Windows PE
executable, both from Eric Zimmerman's MIT licensed test corpus. The second is
there deliberately: a parser that accepts it is not checking its signature.

These are committed rather than generated because a synthetic hive would only
ever exercise the shapes its generator knew to produce, and the awkward parts
of the format - big-data values, the several kinds of subkey list, cells
pointing at each other - are exactly the parts a generator would omit.
